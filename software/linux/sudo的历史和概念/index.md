在一个计算机系统中，存在一种上帝角色——root，它拥有所有权限，可以对机器做出任意的操作（包括自我毁灭）而不受约束，早期的计算机以多用户系统设计为核心，每个用户通过终端机登录同一台中央机器。以使用人员的名字来作为登陆计算机的虚拟用户名是显而易见的，这便于在同一台计算机上完成每个人各自的工作，但问题是计算机中的虚拟世界和现实世界在面临多用户场景下都会碰到同一个难题：每个用户能做什么，能够访问什么？

如果平等分配 root 角色给每一个用户，意味着所有用户都拥有了按下核弹按钮的权力（即毁灭计算机本身），这是非常危险的，过去的历史告诉我们，一个愚蠢的运维操作或者一个不小心的删除操作可能比一个处心积虑的黑客操作破坏力来的更大。所以伴随着操作系统的诞生，很早 Bob Coggeshall 和 Cliff Spencer 就意识到编写一个能够给普通用户有限制的权限获取工具的重要性了。

sudo 作为一种命令行工具，提供了普通用户提权（或者说是系统管理员授权）和审计的框架，一个用户拥有的权限越少，对系统越安全，反之拥有所有权限的 root 对于系统而言是最危险的。

sudo 最初由 Bob Coggeshall 和 Cliff Spencer 在 1980 年前后构思并实现，地点是纽约州立大学布法罗分校（SUNY/Buffalo）计算机科学系。它运行在一台运行 4.1BSD 的 VAX-11/750 上。

Garth Snyder 在 1986 年发布增强版；此后约5年由科罗拉多大学博尔德分校（CU-Boulder）的一小群人维护，其中包括 Bob Coggeshall、Bob Manchek 和 Trent Hein。（Coggeshall 后来也参与了 CU-Boulder 阶段）

Todd C. Miller 自1993年起维护 sudo，他同时也是 OpenBSD 的贡献者，并曾为 ISC cron 做出重要贡献，此后 30 多年来，他一直是 sudo 的维护者，目前正在寻找赞助者来资助后续维护和开发（联想到那张 xkcd 的漫画：https://xkcd.com/2347/，庞大复杂的互联网所依赖的基石开源项目，往往是由少数几个无私的人所贡献的）。

sudo 从 1980 年代的简单设想出发，现在已经成为一种围绕"最小权限原则"的授权框架，其本质思想还是让每一个登陆系统的用户拥有他们开展个人工作所需要的最小权限。类比现实世界中的企业、机构、政府、军队等制度：权力越大，越要把它拆分、限定范围、留下记录，并使每次动用都是有意识的决定。这些思想在计算机出现之前就已经存在于人类组织里，而 sudo 把它们落到了操作系统层面。
