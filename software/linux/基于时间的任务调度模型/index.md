## 前言

自从计算机诞生以来，其最主要的一个任务就是自动化、批处理大量的任务。其中一种触发任务的方式是基于时间，也就是在满足以时间为核心的条件后，触发任务的执行。

本文将简单讨论下各个编程语言中的定时任务框架，以及操作系统中的定时任务软件。

---

## 时间触发规则

时间触发有很多种方式：

- 延迟执行
- 固定间隔
- 固定时间
- 日历规则
- 工作流的等待

延迟执行用于一些订单类任务，比如订单自动在 30 分钟后关闭；固定间隔用于一些指标类的采集，比如固定30分钟采集一次服务器数据；固定时间用于备份和恢复，很多运维会选择编写一个在凌晨3点（服务器使用率较低的时候）对数据库进行备份的脚本，固定时间执行该脚本。日历规则则更加灵活，对于财务结算系统、特殊节日的邮件发送，可以使用日历规则，比如在每个月的最后一个礼拜一进行财务报表的结算的任务。工作流等待则指的是在工作流中有前后任务执行顺序下，后者任务依赖于前者任务的时间（比如完成的时间，或者有效期之类的）。

## 墙上时间和单调时间

CLOCK_REALTIME 是墙上时间，墙上时间（wall clock / realtime clock）表示人类世界中的时间点，例如：

```
2026-11-01 10:30:00 Asia/Shanghai
2026-11-01T02:30:00Z
Unix timestamp: 1793500200
```

墙上时间最大的问题是无法保证单调递增，这在需要严格执行定时任务的场景有时是很致命的，因为以下一些因素，可能会发生墙上时间的跳变：

- 管理员修改系统时间；
- NTP 校时；
- 虚拟机迁移或恢复快照；
- 手机自动校时；
- 系统从休眠恢复；
- 测试环境人为调整时间。

墙上时间因为是现实世界中的有意义的时间，所以可以写入到数据库或者跨进程传递和比较，表达一些有含义的时间（每天上午九点、明天下午两点、或者某个具体时间订单关闭）。

CLOCK_MONOTONIC 是单调时钟，从某个起点时间开始不断增加，起点是什么不重要，重要的是单调时钟是递增的。它不适合像墙上时钟一样表达具体的时间含义，因为单调时钟值离开了本机环境通常没有意义，它更适合的场景是表达超时、重试间隔时间、性能测量、限流窗口、进程内容的延迟执行。

所以单调时钟强调的是值的单调性，适合计算两个时钟值之间的差值，而值本身并没有太多含义。
